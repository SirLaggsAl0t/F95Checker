# F95Checker Web

Standalone web app. The desktop app is not modified; server-side logic is
vendored under `server/vendor/` and owned by this app.

## Quickstart

```bash
python -m venv server/.venv
server/.venv/Scripts/pip install -r server/requirements-dev.txt   # Windows
python server/run.py
```

Open http://127.0.0.1:8642. Set `F95WEB_HOST=0.0.0.0` to expose on the LAN and
`F95WEB_USERNAME`/`F95WEB_PASSWORD` to require HTTP Basic auth (both or
neither).

| Variable | Default | Meaning |
|---|---|---|
| `F95WEB_HOST` | `127.0.0.1` | Bind address; `0.0.0.0` for LAN |
| `F95WEB_PORT` | `8642` | Port |
| `F95WEB_USERNAME` / `F95WEB_PASSWORD` | unset | Enable Basic auth |
| `F95CHECKER_DATA_DIR` | per-OS app dir | Database, images, web cache |
| `F95INDEXER_URL` | `https://api.f95checker.dev` | F95Checker indexer API |

The web app uses its own data dir (`%APPDATA%/f95checker-web`,
`~/.config/f95checker-web` or `~/Library/Application Support/f95checker-web`).

## Sharing with the desktop app

Do not point `F95CHECKER_DATA_DIR` at a live desktop data dir while the desktop
app is running: both processes cache the library in memory and overwrite each
other. Stop the desktop app first, back up the DB, then either use the copy
helper or set the env var explicitly. The schema copy may migrate the DB.

```bash
python scripts/import_desktop_data.py            # default desktop data dir
python scripts/import_desktop_data.py --from /path/to/data --force
```

It copies `db.sqlite3` and `images/`; it never writes to the source.

## Docker

```bash
cp .env.example .env    # set credentials before exposing the port
docker compose up -d --build
```

The compose file publishes `8642` and keeps the data in the `f95checker-data`
volume, so restarts keep the library. The container listens on `0.0.0.0`; the
optional credentials in `.env` decide whether the LAN needs Basic auth.

## LAN access

Allow port 8642 through the Windows firewall (or the host firewall) for the
local network only. Plain HTTP is accepted on a home LAN, but Basic auth is
cleartext there. For anything beyond a trusted LAN, put a TLS reverse proxy in
front, for example Caddy:

```caddyfile
f95.example.lan {
    reverse_proxy 127.0.0.1:8642
}
```

The client is a SPA served by the same server; `/api/*` is never cached by the
fallback and unknown API routes return JSON 404.

## Client

```bash
cd client && npm install
npm run dev     # proxies /api to 127.0.0.1:8642
npm run build
npm test
```

Brand assets and the MDI webfont are generated by `python scripts/sync_assets.py`.
Tab icons render the raw `Tab.icon` glyph with that font; enum icons use
`@mdi/js` paths directly (`components/Mdi.tsx`).

Views: list, grid and kanban (group by status, type or label; the card menu
moves a game). Settings (`/settings`) covers refresh flags, previews, theme
colours/presets, tag highlighting, hidden timeline event types and the proxy.
The timeline page (`/timeline`) groups events by day. Background refresh runs
through the same single-worker queue as manual refresh; `0` minutes disables it.

## Tests

```bash
server/.venv/Scripts/python -m playwright install chromium   # once
server/.venv/Scripts/python -m pytest server e2e
```

E2E tests start uvicorn in-process with a throwaway data dir and mock the
network at the server layer, so they never hit F95zone. `e2e` needs the built
client (`npm run build` in `client/`).
